# KIN v0.2 — Technical foundation

Status: development proposal, not production-ready.

## Product invariants
1. Discovery responses never include identifying profile fields.
2. Identity reveal requires independently recorded consent from both parties.
3. Revoking consent prevents subsequent identity reads.
4. Blocking prevents further discovery, reveal and messaging at the service boundary.
5. Never interpret fictional confidence scores as real genetic evidence.
6. Real DNA/ancestry or precise location processing is out of scope until a privacy and legal review.

## Recommended boundaries
- `DiscoveryService`: return non-identifying candidate cards.
- `ConsentService`: record/revoke consent per connection and user.
- `RevealService`: authorize identity reads only after mutual consent and no blocks.
- `SafetyService`: block, report and moderation workflow.
- `MessageService`: allow messages only for eligible connections.

## Suggested API (future backend)
- `GET /api/discovery`: pseudonymous discovery cards only.
- `POST /api/connections/:id/consent`: authenticated consent or revocation.
- `GET /api/connections/:id/reveal`: authenticated, server-authorized identity read.
- `POST /api/connections/:id/block`: authenticated block.
- `POST /api/reports`: moderation intake.

These are contracts to discuss, **not** endpoints implemented in this PR.

## Acceptance tests for implementation
- One-sided consent returns no identity.
- Mutual consent returns identity only for the two eligible participants.
- Revocation immediately denies further reads.
- Either participant's block denies reveal and messaging.
- Invalid connection IDs and unauthenticated requests are rejected.
- No identifying fields leak through discovery payloads or logs.

3. Add domain tests at the service boundary.
4. Introduce backend persistence and authentication before processing real user data.

## Honest prototype status
The current README describes simulated location, consent, family connections and chat. No claims of secure matching or production privacy protection are made.
